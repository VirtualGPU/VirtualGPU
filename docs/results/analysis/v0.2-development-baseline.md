# v0.2 development-set baseline before the freeze

**A record, not a decision.** These are the v0.2 core's scores on the development sets, taken before the v0.2 freeze so that later changes can be compared against them. The development sets were used throughout v0.2 development, so these numbers say nothing about how v0.2 does on unseen workloads; that is what the preregistered holdout evaluation (`validation/v02-preregistration.md`) is for.

## Setup

- Core: `edb9ee6`, formal build (not dirty). Its code is that of `main` `29a6ac2`; the commit changes only `docs/design.md`.
- Profile: `rtx4070` `0.21.0-posthoc`.
- KernelIR: regenerated with the frontend at `29a6ac2` (GEMM from the shapes and configs of the M2 development AOT IR; attention with `TRITON_DEFAULT_FP_FUSION=1`). Outside metadata and diagnostics it is identical to the IR used in the v0.2 mechanism checks.
- Predictions: 32 perturbed draws plus the nominal profile, round-robin dispatch.
- Scoring: `validation.score` with `--aot` for every config and `--core-revision`. All 34 scores are `formal`, and all 2658 artifact checks are `matched`. A second run on the same commit gave identical scores.
- Measurements: the GEMM development suite of M2 (nine cases; cold from the clean-cold capture) and the attention development set measured at `fde371d` (eight cases). No holdout data were used.

Error is predicted over measured median, minus one; MAPE is over the scored configs of each score. `m1-cube` and `swizzle-320` have one and two configs, so no tau.

## Known residuals in these numbers

- GEMM configs with `num_stages = 1` are predicted slow (design 9.2), most visibly in the warm `mask-m` and `sm-round` cases.
- `swizzle-320` is 22% slow on both of its configs.
- v0.2 does not charge spill reload latency (design 9.2). On the attention development set this does not show: the 24 config and cache points with at least 100 B of spill loads per thread have median error +0.6% (-7.8% to +9.3%), against +1.9% for the others. It does show on the opened `mask-mnk` holdout (post-hoc, `posthoc-core-phase1-phase2.md`).
