## Residency and recheck

Each CTA entering a phase after same-timestamp departures and refills
uses the actual resident count on its SM for the frame footprint,
per-CTA traffic split and reload latency. The charge stays fixed through
the phase. The peak realized count still seeds persistent L2 spill
pressure. Tests cover sparse and evenly filled grids, an uneven wave,
a full wave and a sparse tail.

All 2,807 recheck predictions are bit-identical to the first-wave base.
On the eight legacy spill rows, the fixture has one CTA per SM, so the
two implementations use the same spill charge. Their signed median
and MAPE remain +67.6% and 54.9% (GB10) and +38.0% and 35.0%
(RTX 4070). The rest of the suite carries no spill charge.
[Refreshed baseline](v0.3-mechanism-recheck-baseline.md)

The synthetic full-wave-plus-one-CTA witness uses a 1 KiB frame
and 128 reloads per thread. The first-wave base predicts 18,391.6 ns
per step of extra time on GB10 and 18,469.0 ns on RTX 4070. The
per-SM candidate predicts 15,235.0 ns and 17,754.5 ns respectively.
The base is 20.72% and 4.02% higher. There is no corresponding
hardware measurement. The legacy spill values still lack a qualifying
long-launch capture.

## Issue #21 freeze gate

**The clarified gate passed.** LukeGus confirmed that the original
control must reproduce every byte and a clean candidate may differ
only in `core.commit`. [Issue #21 clarification](https://github.com/VirtualGPU/VirtualGPU/issues/21)

The original clean `cd5f35f` build
reproduces the registered output byte for byte. The clean candidate
`01190e9` changes only the value of `core.commit`. The script and
profiles, build class and dirty flag, and every prediction match
without any other byte changes. The raw candidate file has a different
SHA-256 because it identifies its own build.

The frozen RTX 4070 profile was hashed with CRLF line endings. To
recreate the input, use a private working directory with `profiles/`.
Copy the tracked GB10 profile there byte for byte. Read the tracked
RTX 4070 file as bytes, confirm it contains LF and no CR, replace
each `b"\n"` with `b"\r\n"`, and write that copy. Verify the two
digests against the registered JSON before running the scorer:

- GB10 `10625fa4832c864fcba4d81c9b99480e58f69c81644a9950083b702488442471`
- RTX 4070 `589579415b2c05b2e7d70be6b2616936bcdbfad4c8cb3c43e9febaacd6dbb8b6`

Run from the private directory with each clean build installed in its
own environment. Keep the relative profile paths as shown, since the
scorer records them in the JSON.

```sh
CUDA_VISIBLE_DEVICES="" python "$REPO/scripts/spill_decision.py" freeze \
    --profile gb10=profiles/gb10.json --profile rtx4070=profiles/rtx4070.json \
    --out "$OUT"
```
