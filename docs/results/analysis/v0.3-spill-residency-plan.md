# Spill frame residency correction preregistration

Registered against `0c0f83e` before implementation. This CPU-only check is
provisional. It uses archived microbenchmarks and replays archived IR without
workload labels. It leaves the frozen v0.2 conclusions in force.

## Proposed charge

At entry to the phase that executes the spill scope, count the actual CTAs
resident on that CTA's SM after all same-timestamp completions and refills.
Charge the spill lookup for
`stack_frame_bytes_per_thread * warps_per_cta * warp_size * resident_ctas`.
Divide the resident group's spill traffic by its CTA count to recover the
per-CTA charge. Use the same footprint and miss fraction for the reload
latency. The charge stays fixed for the phase, as do other phase demands.
Maintain the existing persistent L2 spill pressure policy, seeded by the
highest realized resident count at initial dispatch, and keep the spill
traffic split's initial L2 working-set convention. Full-wave launch and
steady-state charges use the same inputs as before. Partial waves, sparse
grids and phases entered after other CTAs leave can use smaller footprints.
The scheduling policy, hardware occupancy, profile curves and spill-scope
scaling stay fixed.

## Decision rule

- Test a single resident CTA under a higher hardware limit, an uneven first
  wave, a partial tail, and a constant full-residency spill case. The
  spill-bearing phases must use the expected per-SM counts. The active
  threads and local bytes charged per CTA must agree with the IR. Traffic
  across L1, L2 and DRAM must sum to the input spill traffic. The charge for a
  full-residency phase must reproduce the previous charge.
- Run `scripts/recheck_mechanisms.py` on the two current reference profiles
  with independent builds of the base and candidate. Use all four
  `l1_boundary` batch-before-dependency points with nonzero reload count on
  each device. The endpoint is the predicted extra time per step against the
  matched zero-reload case. On each device, the signed median error must
  move toward zero and both median absolute percentage error and mean
  absolute percentage error must strictly decrease. All predictions for the
  unchanged mechanisms must be identical. Reject if any condition fails.
  These rows are legacy short-launch data from
  [the mechanism recheck baseline](v0.3-mechanism-recheck-baseline.md).
  The first long-launch GB10 spill capture failed the dispersion protocol and
  is excluded from the decision. The archived
  [carveout diagnostic](gb10-spill-carveout-plan.md) provides context for the
  unresolved L1-boundary instability. Passing this check supports the
  occupancy correction provisionally. It does not validate the empirical spill
  latency table or the estimated local pipe bandwidth.
- Replay all four archived v0.2 IR cohorts on both reference devices with
  their current profiles, in warm and cold modes, with 32 draws and seed 17.
  Preserve the revision, IR/profile digests and raw predictions. Spill-free
  rows must be bit-identical in nominal time and draws, with unchanged
  statuses. Only spill-bearing rows may change and those rows must keep
  their statuses. Report any changes confined to draws separately. No
  workload labels enter this check.
