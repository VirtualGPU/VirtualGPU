# H5 on GB10: amendment to the redo registration

Status: amends [the GB10 redo registration](v0.3-gb10-h5-redo-registration.md), before any capture under it, as the author of the H5 roadmap item asked in PR #32. The implementation (`fe8e2d7`) has been compiled and reviewed; no point has been measured. Nothing below changes after the GB10 capture is taken.

## What changes

- **GB10 captures form (a) only**, the `h5-dram` mode: the DRAM-side narrow request form, with its points, protocol, design choices and pass rule as registered.
- **Form (b) is not captured again on GB10.** Its verdict there is the existing one on `stage-narrow-k1-2`, the one qualified H5 capture: MAPE 15.7% on 92 points against the 15% limit, every width's median error within 10%, not passed ([h5-followups-gb10-posthoc.md](h5-followups-gb10-posthoc.md)). A second capture on the same points would be a second draw of a test that already has a valid failed result, so none is taken. The `h5-staging` mode and its scoring stay in the implementation and are not run on GB10.
- **The RTX 4070 half captures both forms**, registered separately when a window is given.

## Decision, rewritten

The registration's decision section is replaced by this one:

- The GB10 half of H5 consists of the new verdict for form (a) under this protocol and the existing verdict for form (b) on `stage-narrow-k1-2` (not passed).
- A form goes into the core only if it passes on both GPUs: on GB10, (a) by the new capture, and (b) by its existing verdict, which it did not pass. So (b) cannot go into the core in v0.3.0 whatever the RTX 4070 shows. Its RTX 4070 result is reported as a cross-GPU measurement.
- If (a) fails on GB10, or is not judged because its capture fails, it does not go into the core in v0.3.0, and no further GB10 attempt is registered. If it passes, it goes into the core only if it also passes the RTX 4070 half.
- Reported either way for the GB10 capture: every round's gates and rule counts, rule 3, the calibration value from each process, every point's measured value and errors, and the exclusions with their reasons.

Everything else in the registration is unchanged.
